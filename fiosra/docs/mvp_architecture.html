Fiosra MVP Architecture & Engineering Specification

A definitive architectural blueprint and systems manual for engineers and educators. Specifies the 3-agent functional topology, hybrid Neo4j + pgvector cognitive graph layer, the Language and History MVP evaluation domain via Natural Language Inference (NLI), and the immutable session event store powering AutoSCORE Light evidence dossiers.

Topology: 3 Functional Agents MVP Domain: Language & History (NLI Entailment) Hybrid Data: Neo4j 5 Graph + pgvector 16 Storage: PostgreSQL 16 JSONB Flight Recorder Evaluation: AutoSCORE Light (AAAI 2026)

1. Overview & Core Architectural Principles

Traditional learning management software measures only terminal outcomes: whether a student arrived at the final right answer. In the age of conversational LLMs, terminal grading is fundamentally broken because students can outsource both computation and prose. Fiosra is a cognitive reasoning infrastructure layer that monitors, preserves, and evaluates the complete learning trajectory through structured, answer-blind dialogue and deterministic verification.

Rule 1: Strict Answer Isolation The student-facing conversational model (Dialogue Agent) never has the reference answer, thesis, or completed calculation in its generation prompt. Only the isolated Integrity Agent has access to ground-truth answers. This eliminates prompt injection attacks where students attempt to extract solutions.
Rule 2: Deterministic Verification Outranks LLMs Verification is strictly separated from dialogue generation. Objective verification engines (Natural Language Inference claim checkers for essays and symbolic computer algebra for math) render correctness decisions—never the conversational LLM's subjective impression.
Rule 3: Sovereign Teacher Authority AI never issues unilateral final grades or permanent credential changes. The Evidence Agent synthesizes an auditable Structured Evidence Packet ($Z$) with verbatim student citations, enabling educators to verify student learning trajectories and approve or override assessments in under 15 seconds.

4. Build Sequence & Dependency Map

Building Fiosra requires strict dependency sequencing: low-level data and event persistence must precede verification rules, which in turn must precede dialogue generation. The recommended 7-phase build order is:

1 Phase 1: Storage Infrastructure & Core Schemas
Provision PostgreSQL 16 with pgvector, uuid-ossp, and Neo4j 5 database instances. Establish base schema tables: knowledge components, sessions, event store, and vector embeddings. Establish Neo4j uniqueness constraints and relationship schemas.
2 Phase 2: Hybrid Knowledge Layer (Neo4j + pgvector)
Implement graph services for prerequisite traversal, concept ancestor lookup, and misconception mapping in Neo4j. Implement vector similarity search in pgvector for semantic error matching. Seed initial curriculum taxonomy for History and Language.
3 Phase 3: JSON Event Store (Flight Recorder)
Build high-throughput append-only event ingestion pipeline with PostgreSQL JSONB and GIN indexing. Implement session lifecycle management, chronological ordering, and timeline retrieval for replay.
4 Phase 4: Integrity Agent & Pluggable Verifiers
Build the isolated Answer Vault repository. Implement deterministic Natural Language Inference (NLI) claim entailment verifier for textual reasoning. Implement the session hint ceiling algorithm and teacher override gates.
5 Phase 5: Dialogue Agent (Answer-Blind Socratic Tutor)
Author prompt engineering harnesses enforcing strict negative constraints (no solutions, no answers, no calculations). Implement the CLASS cognitive diagnostic reflection step and the 4-rung graduated hint delivery engine.
6 Phase 6: Evidence Agent & AutoSCORE Light Dossier
Implement chronological event stream replay to synthesize Structured Evidence Packet ($Z$). Calculate the 5 core learning metrics (Autonomy rating, self-corrections, hint ratio, dwell time, misconception resolution). Generate the 1-page teacher review dossier with clickable citations.
7 Phase 7: Assignment Designer & UI Integration
Build educator curriculum ingestion and misconception trap seeding. Connect Next.js presentation frontends (Educator Studio & Student Reasoning Canvas) via FastAPI backend routers.

5. The Three Functional Agents

Rather than relying on unconstrained, monolithic chatbots, Fiosra separates agent responsibilities into three functional roles with strict privilege boundaries:

1. Dialogue Agent (Socratic Reasoning Tutor) Student-Facing Partner

Primary Mission: Facilitate deep, autonomous problem-solving through guided inquiry without ever performing the cognitive labor for the student.

Core Operating Constraints:

  • Answer-Blindness: Operates without the target solution, reference thesis, or final values in its context window.
  • Negative Constraints: Never completes equations, writes full thesis sentences, or confirms final values unassisted.
  • CLASS Diagnostic Reflection: Performs internal cognitive reflection before formulating each conversational response.
  • Hint Ceiling Enforcement: Constrained to the maximum allowable hint level permitted by the Integrity Agent.

Graduated 4-Rung Hint Hierarchy:

Rung Pedagogical Nature Agent Delivery Behavior Access Condition
Level 0 Metacognitive Probe Prompts self-monitoring: "What initial condition must hold before proceeding?" Attempt 1 (Always Available)
Level 1 Conceptual Principle States relevant domain definitions or historical context without applying them to the current problem. Attempt 2, or prior low mastery
Level 2 Procedural Step Suggests the immediate next sub-action without computing or writing the result. Attempt 3
Level 3 Worked Analogy Presents an isomorphic problem with completely different entities or numbers. Attempt 4+
Level 4 Bottom-Out Solution Complete explanation and solution. Strictly locked in MVP. Teacher Override Only
2. Integrity Agent (Policy, Answer Vault & Verifiers) Ground-Truth Guardian

Primary Mission: Guard ground-truth solutions in complete isolation, execute objective correctness verification, and mathematically govern hint ceilings.

Core Operating Invariants:

  • Isolated Answer Vault: Keeps reference answers secured away from student access and dialogue context.
  • Objective Verification Over Probabilistic LLMs: Evaluates student claims through deterministic logic engines rather than conversational LLM guesses.
  • NLI Claim Verifier (MVP): Uses Natural Language Inference (premise-hypothesis entailment) to verify whether student essay arguments satisfy rubric criteria.
  • Deterministic Hint Ceiling Function: Calculates allowable hint rungs purely from attempt counts, elapsed time, and prior mastery.

Integrity Evaluation Matrix:

Verification Mode Target Domain Evaluation Engine Success Metric & Output
NLI Entailment (MVP) History & Language Reasoning Natural Language Inference (Entailment Model) Classification: MET, PARTIALLY_MET, or MISSING with citation snippet
Symbolic Equivalence (Post-MVP) STEM & Mathematics SymPy Computer Algebra System Mathematical difference simplification to zero; syntax error detection
AST Sandboxed Execution (Future) Computer Science & Coding Isolated Docker / WASM Test Runner Unit test pass/fail assertion, runtime boundary check
3. Evidence Agent (Trace & AutoSCORE Light Dossier) Pedagogical Synthesizer

Primary Mission: Replay the chronological interaction stream to reconstruct the student's authentic learning trajectory, compile Structured Packet $Z$, and provide teachers with 1-click verifiable grading dossiers.

AutoSCORE Light Two-Stage Pipeline (AAAI 2026):

  • Stage 1 ($f_{\text{extract}}$): Replays raw keystrokes, dialogue turns, verifier checks, and hint requests to extract 5 core diagnostic metrics into Structured Evidence Packet $Z$.
  • Stage 2 ($f_{\text{score}}$): Evaluates Packet $Z$ against the assignment rubric, pairing every grade recommendation with exact clickable quotes from the student's work.

The 5 Core Learning Trajectory Metrics:

Metric Operational Definition Pedagogical Meaning
Autonomy Rating Ratio of subproblems resolved without accessing Level 2+ hints. Measures student independence and self-directed problem-solving capacity.
Self-Correction Count Number of instances where an initial verification failure was corrected following a Level 0/1 prompt. Indicates productive struggle, critical self-monitoring, and resilience.
Hint Dependency ($H_d$) Total hint requests divided by total steps attempted. Identifies students who over-rely on scaffolding vs. work independently.
Dwell Time Trajectory Time spent reading feedback and revising vs. rapid guess clicking. Distinguishes genuine reflection from guessing and trial-and-error gaming.
Misconception Remediation Resolution status of diagnosed conceptual errors during the session. Verifies whether flawed cognitive rules were unlearned and replaced with correct concepts.

6. Supporting Infrastructure Services

The 3 functional agents are supported by three specialized platform services:

A. Hybrid Knowledge Layer (Neo4j 5 + pgvector 16)

Curriculum concepts form hierarchical, multi-hop dependency graphs, while student misconceptions require semantic vector similarity matching. Fiosra pairs Neo4j with pgvector in a hybrid topology:

Neo4j Graph Engine Structural Cognitive Map

Responsibilities:

  • Maintains Concept node hierarchies across domains, subjects, and grade levels.
  • Enforces Directed Acyclic Graph (DAG) constraints on REQUIRES_PREREQUISITE edges.
  • Traverses ancestor prerequisites with sub-millisecond graph queries.
  • Links Misconception nodes to target concepts via EXEMPLIFIES_MISCONCEPTION edges.
PostgreSQL pgvector Semantic Similarity Store

Responsibilities:

  • Stores 1536-dimensional embeddings of cataloged misconceptions and curriculum texts.
  • Executes fast cosine distance search to classify student error text against known misconceptions.
  • Identifies novel student misunderstandings that fall below the similarity threshold (< 0.82) for educator review.

B. JSON Event Store (Append-Only Flight Recorder)

Learning occurs during the intermediate steps, not at the final submission. The Event Store records every student interaction as an immutable, timestamped row with a PostgreSQL JSONB payload:

  • Event Types Logged: session_started, step_attempted, verifier_evaluated, hint_requested, hint_delivered, self_correction_achieved, session_completed.
  • Indexing Strategy: GIN indexing on the JSONB payload for sub-second attribute lookups, paired with composite chronological indexing on (session_id, created_at ASC) for real-time replay.
  • Auditability: Because the log is append-only, student trajectories cannot be tampered with or retroactively altered.

C. Assignment Designer & Syllabus RAG

Enables educators to convert curriculum outlines, syllabi, and textbook excerpts into structured, misconception-seeded problem sets:

  • Prerequisite Verification: Checks the Neo4j graph to confirm all prerequisite concepts exist and are appropriately sequenced.
  • Misconception Traps: Seeds multiple-choice options and scaffolding checks with known cognitive traps from the taxonomy, ensuring every error delivers diagnostic signal.
  • 4-Rung Ladder Generation: Pre-authors calibrated hint hierarchies for each problem sub-step.
  • Automatic Vault Registration: Directly registers reference answers with the Integrity Agent's Vault upon teacher approval.

D. Course, Module & Cohort Context

Maintains institutional scoping so that learning analytics, misconception frequencies, and student autonomy trajectories roll up cleanly from individual sessions to module, course, and cohort levels for departmental insights.

7. End-to-End System Walkthroughs

Primary MVP Walkthrough: French Revolution Essay Analysis (Humanities)

Assignment Prompt: "Analyze the primary economic and social causes of the French Revolution in 1789, specifically assessing the financial crisis of the Crown and the grievances of the Third Estate."

Stage 1: Rubric & Knowledge Configuration
The Assignment Designer provisions three typed claim criteria in the Integrity Agent's Vault:
  • Criterion A (Fiscal Breakdown): Student must articulate royal debt resulting from Seven Years' War and American Revolution support.
  • Criterion B (Social Inequality): Student must cite specific tax burdens (taille, corvée) and voting disparities borne by the Third Estate.
  • Criterion C (Enlightenment Influence): Student must link intellectual challenges (Rousseau, Sieyès) to divine-right monarchy.
Stage 2: Student Draft Submission & Verification
Student Initial Draft: "The French Revolution started because the king wasted all the country's money on palaces and the people got really mad because they were poor and had to pay everything."
Execution Flow:
  1. Student draft is submitted to the Integrity Agent.
  2. Natural Language Inference (NLI) claims verifier checks draft against criteria:
    • Criterion A: PARTIALLY_MET (Mentions royal spending, but misses geopolitical wars and national debt).
    • Criterion B: PARTIALLY_MET (Mentions paying everything, but fails to identify the Third Estate or specific taxes).
    • Criterion C: MISSING (No mention of Enlightenment philosophies).
  3. Integrity Agent sets hint_ceiling = 1 (Conceptual hint allowed).
  4. Event Store records verifier_evaluated with full claim analysis.
Stage 3: Dialogue Agent Socratic Scaffolding
Diagnostic Reflection: Student recognizes fiscal crisis and inequality, but relies on informal intuition without identifying the Three Estates hierarchy or formal taxes. Nudge toward the social structure.
Dialogue Agent: "You've highlighted a genuine grievance regarding who carried the financial burden! In 1789, French society was formally divided into three distinct groups. What was the name of the group that made up over 95% of the population, and what specific taxes did they bear that the nobility avoided?"

The Event Store records hint_delivered at Level 1.

Stage 4: Student Revision & Self-Correction
Student Revised Draft: "The French Revolution erupted because the Crown was bankrupt after funding the American War of Independence. Under the Ancien Régime, the First and Second Estates paid virtually no taxes, leaving the Third Estate—over 97% of the population—to shoulder the taille and feudal tithes without any voting power in the Estates-General."
  1. Integrity Agent NLI verifies: Criterion A = MET, Criterion B = MET.
  2. Event Store logs self_correction_achieved.
  3. Dialogue Agent congratulates the student on historical precision and prompts reflection on the remaining Enlightenment criterion.
Stage 5: Evidence Agent Synthesizes AutoSCORE Light Dossier
The Evidence Agent compiles Structured Evidence Packet $Z$:
  • Autonomy Rating: 82% (Student successfully revised upon Level 1 conceptual guidance).
  • Self-Corrections: 1 validated self-correction from informal grievance to historical terminology.
  • Citations: Exact verbatim quotes paired with Criteria A and B.
  • Recommended Grade: Proficient (A-) pending Criterion C exploration.

The teacher views the 1-page dossier in Educator Studio and approves the assessment in 12 seconds.

Post-MVP Extension Walkthrough: Linear Algebra Problem (STEM)

Problem: Solve for $x$: $4(2x - 3) = 20$.

1. Student Attempt with Partial Distribution Error
Student Input: 8x - 3 = 20

Integrity Agent dispatches equation to SymPy CAS. SymPy computes $(8x - 3) - 20 \neq 0$ (Incorrect). pgvector matches the expression with misconception MISC_DIST_PARTIAL (cosine similarity 0.94): "Student multiplied 4 by 2x but failed to distribute 4 to -3."

2. Calibrated Socratic Prompting
Dialogue Agent: "You correctly multiplied the 4 by the 2x! Now look carefully at the parentheses: what happens when the 4 is applied to the second term inside?"
3. Self-Correction Verification
Student Input: 8x - 12 = 20 => 8x = 32 => x = 4

SymPy confirms equivalence. Event Store records self-correction. Autonomy score preserved.
